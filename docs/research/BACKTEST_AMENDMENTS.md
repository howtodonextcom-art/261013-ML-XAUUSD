# P6 amendments and deviations (recorded after the first dev/validation run; no holdout bar was read)

Source: independent review of the P6 engine (2026-10-14, read-only subagent). Every item is either fixed in code (with a regression test) or disclosed here. The frozen documents (BACKTEST_PREREGISTRATION.md, BACKTEST_IMPLEMENTATION_CLARIFICATIONS.md) were NOT edited. The fixes were not independently re-reviewed.

| # | Item | Disposition |
|---|---|---|
| A1 | Segment / embargo rule | Pre-registration: a trade open at a boundary is dropped from the LATER segment. Implemented: the dev/val cut is a hard data cut, so a trade crossing `dev_end` is dropped from the EARLIER segment (stricter isolation); validation trades unresolved at `val_end` are dropped as DATA_ENDED; walk-forward blocks use no embargo. Accepted deviation, disclosed. |
| A2 | Walk-forward | Pre-registration said "4 expanding folds". Implemented: 4 disjoint equal-time blocks over development+validation. They overlap the dev and val segments, so they are NOT independent evidence beyond those segments. No parameter is fitted, so expanding training windows would change nothing. |
| A3 | Metrics | Exposure and trades per week were pre-registered but are not computed; "by regime" is the H1 direction context only; month concentration uses 30-day buckets. |
| A4 | Bar exclusion | Quarantined bars are now excluded in `load_bars` (the M5-H4 stores currently contain none for this symbol/server). M1-hole buckets are irrelevant: decisions use native M5/M15/H1/H4 bars. |
| A5 | SELL stop trigger | A SELL stop is a buy order and triggers on the ask. Fixed: `ask_side_stops` (bid high + spread >= SL). No dev/val trade changed (independent plain-loop re-simulation, 0 mismatches). |
| A6 | Spread realism | The stored M5 spread is mostly 0.04 or 0.00 (monthly medians 0.13-0.16 in Oct-Nov 2025, constant 0.04 Jan-May 2026, 52% zeros in June 2026, 0.10-0.14 later). Added cost levels `spread0.2` and `spread0.4` (spread floor) to every result; they must be read before interpreting any later period. A later holdout with larger spreads would reflect a cost regime, not necessarily the strategy. |
| A7 | A trade absent at one cost level | A higher slippage can turn a fill into NO_FILL. Fixed: R is None at that level only; the statistics skip it (the earlier code would have crashed). |
| A8 | Seal and holdout mechanics | Fixed: split points are frozen in `results/p6/boundaries.json` at the first run and again in the seal; the seal stores boundaries, code SHA, config hash and the dev/val dataset hash; a seal is never overwritten; bars appearing after the seal are ignored; the opened marker is written before any holdout number is computed and records STARTED / COMPLETED / CRASHED; every dev/val run is appended to `devval_runs.jsonl`; `--dry` runs the whole holdout pipeline on the VALIDATION window. Limit: marker and log are plain files; commit them. |
| A9 | Wording | "never loaded / not in memory" was an overclaim: the store read loads all bars and they are dropped before any computation. The timeout is 288 M5 bars, not 24 h. C5 is not a pure zone removal (see the report). C6 equals C4 by construction. |
| A10 | Power | The pre-registered 100-trade holdout rule is unreachable with this data (about 7 expected holdout trades). The holdout can only ever return INSUFFICIENT_EVIDENCE. Stated up front. |
| A11 | Structure-only contamination | The swing-k experiment and the setup-lifecycle design used the whole year (including the future holdout) for structure only, never for P/L. |
| A12 | Tests | Weak assertions tightened; new tests: ask-side SELL stop, spread floor, per-level absent trade, `spread_at` / `last_closed_m5`, seal verification, fixed boundaries. Not covered: look-ahead mutations inside ATR / known_at / align_to (the detector test mutates `direction_series` only). |
| A13 | Re-run after the fixes | The dev/val run was repeated after the fixes (same data hash 72d57c00...); C4 base-cost R per trade is unchanged; the trade-record fingerprint changed only because the records now carry two more cost levels. |
